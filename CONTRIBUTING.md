## Code de Conduite

Ce projet adhère à un Code de Conduite. En participant, vous vous engagez à respecter ce code. Veuillez lire [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) pour plus de détails.

## Comment puis-je contribuer ?

### Signaler des Bugs

Avant de créer un rapport de bug, veuillez vérifier qu'il n'existe pas déjà une issue similaire. Si vous créez une nouvelle issue, incluez autant de détails que possible :

- **Titre clair et descriptif**
- **Description détaillée du problème**
- **Étapes pour reproduire le bug**
- **Comportement attendu vs comportement observé**
- **Captures d'écran** si applicable
- **Environnement** (OS, version du logiciel, etc.)

### Suggérer des Améliorations

Les suggestions d'améliorations sont également les bienvenues ! Ouvrez une issue avec :

- **Titre clair et descriptif**
- **Description détaillée de l'amélioration proposée**
- **Justification** de pourquoi cette amélioration serait utile
- **Exemples d'utilisation** si applicable

### Contributions de Code

1. **Fork** le projet
2. **Créez une branche** pour votre fonctionnalité (`git checkout -b feature/AmazingFeature`)
3. **Committez vos changements** (`git commit -m 'Add some AmazingFeature'`)
4. **Push vers la branche** (`git push origin feature/AmazingFeature`)
5. **Ouvrez une Pull Request**

## Processus de Pull Request

1. Assurez-vous que votre code respecte les standards de code du projet
2. Mettez à jour la documentation si nécessaire
3. Ajoutez des tests pour toute nouvelle fonctionnalité
4. Assurez-vous que tous les tests passent
5. Mettez à jour le CHANGELOG.md avec les détails de vos changements
6. Votre PR sera examinée par les mainteneurs du projet

## Standards de Code

- Suivez les conventions de nommage du projet
- Commentez votre code lorsque nécessaire
- Écrivez des messages de commit clairs et descriptifs
- Utilisez le format : `type(scope): description`
  - Types : `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
  - Exemple : `feat(auth): add login functionality`

## Tests

- Ajoutez des tests pour toute nouvelle fonctionnalité
- Assurez-vous que tous les tests existants passent
- Visez une couverture de code élevée

## Documentation

- Mettez à jour le README.md si vos changements affectent l'utilisation du projet
- Documentez les nouvelles fonctionnalités
- Mettez à jour les commentaires de code si nécessaire

## Questions ?

N'hésitez pas à ouvrir une issue pour toute question sur le processus de contribution !

Merci pour vos contributions ! 🙏
